# Chrome 웹스토어 한국어 등록 문안

작성일: 2026-10-15. 기준: 현재 `extension/manifest.json`의 **v0.4.0** 및 동봉 실행 소스. 이 문서는 **미제출 초안**입니다. 계정 등록·결제·게시·심사 제출을 수행하지 않았으며, 실행 파일·매니페스트·버전을 변경하지 않았습니다. 절차·비용·이미지 파일 안내는 [등록 안내](README.md)를 함께 확인합니다.

**제출 전 해결 항목:** 현재 매니페스트의 `activeTab`은 확인된 사용 방식에 필요하지 않습니다. 별도 제출 후보에서 제거한 뒤 기능과 패키지를 재검증해야 합니다. 실제 Chrome의 제출 후보에 대한 최종 소량 파일 저장 확인도 남아 있습니다.

## 상세 설명: 아래 일반 텍스트만 복사

```text
네이버 블로그 개별 게시글의 본문 사진을 미리보고, 필요한 사진을 선택해 Chrome 다운로드 폴더에 저장하세요.

주요 기능
• 본문 사진 미리보기와 개별 선택·전체 선택
• w3840 이미지 주소 우선 요청과 대체 주소 재시도
• 다운로드 폴더 아래의 사용자 지정 하위 경로와 게시글별 폴더
• 저장 진행 상태, 실패·중지 상태, 확인된 실제 파일 경로 표시
• 진행 중인 작업 중지와 완료 파일의 저장 폴더 열기
• 시스템 설정 따르기·라이트·다크 화면 모드

사용 방법
1. blog.naver.com 또는 m.blog.naver.com의 개별 게시글을 엽니다.
2. 확장 아이콘을 눌러 본문 사진 목록을 확인합니다. 사진이 늦게 나타나면 본문을 스크롤한 뒤 팝업의 다시 찾기를 누릅니다.
3. 처음 나타난 사진은 선택되어 있습니다. 저장하지 않을 사진의 선택을 해제하고 하위 폴더를 확인합니다.
4. 선택한 이미지 저장 버튼을 누릅니다. 기본 하위 폴더는 NaverBlog이며 게시글별 폴더가 만들어집니다.
5. 완료 카드에서 진행 결과와 실제 저장 경로를 확인합니다.

자동 스캔과 수동 저장
접근이 허용된 네이버 블로그 페이지에서는 본문 구조와 제목·게시글 주소·이미지 주소를 자동으로 확인하여 미리보기 목록을 준비합니다. 페이지를 열거나 사진을 선택하는 것만으로 파일 저장을 시작하지 않습니다. 사용자가 저장 버튼을 누르면 작업을 시작하며, 이미 요청한 작업은 팝업을 닫아도 계속되거나 Chrome 재시작 후 복구될 수 있습니다.

화질과 수집 범위
w3840은 서버에 요청하는 이미지 주소의 우선순위입니다. 실제 가로 3840픽셀, 원본 해상도, 모든 사진의 성공적인 저장을 보장하지 않습니다. 서버가 제공하는 크기와 형식, 접근 권한, 게시글 구조에 따라 결과가 달라집니다. 알려진 실패에서는 type 옵션을 제거한 대체 주소를 시도합니다.
본문의 사진을 대상으로 하며 인식 가능한 스티커·댓글·프로필·사이드바 이미지를 제외하고 같은 이미지 주소를 중복 제거합니다. 모든 글에서 네이버 사진 뷰어의 숫자와 항상 일치하지는 않습니다. 블로그 전체나 여러 글을 자동 순회하는 기능은 없습니다.

화면 모드와 제목 테마
기본 화면 모드는 시스템 설정 따르기입니다. 라이트·다크를 직접 선택할 수도 있습니다. 읽어온 게시글 제목에 ‘아이유’라는 글자가 포함되면 팝업에 응원봉 모양 장식과 응원 문구가 표시되는 팬 테마가 적용됩니다. 제목 조건은 사이트 계정이나 심사 환경에 따른 것이 아니며 다운로드 방식은 같습니다. 일반 제목으로 바뀌면 기본 팔레트로 돌아갑니다. 오픈소스 안내 페이지는 팝업에서 열 때의 테마를 이어받습니다.

데이터 처리
게시글 제목·주소·이미지 주소·크기 정보를 미리보기와 선택 저장에 사용합니다. 스캔 결과는 세션 저장소에, 저장 요청 작업·실제 파일 전체 경로·상태·폴더 설정·화면 모드는 기기의 확장 저장소에 보관합니다. 종료 작업은 최근 30개, 진행 로그는 최근 60개를 유지하며 진행 중인 작업은 별도로 남깁니다. 로그에는 제목·URL·파일명을 넣지 않습니다.
확장에는 개발자 서버로 보내는 분석·추적 기능이 없습니다. 사진 미리보기와 저장에는 네이버 이미지 서버에 대한 네트워크 요청이 필요합니다. 확장 삭제 후에도 이미 저장한 사진과 Chrome 자체 다운로드 기록은 별도로 남을 수 있습니다. 자세한 처리·보관·삭제 범위는 개인정보처리방침을 확인해주세요.

이 확장은 NAVER, 아이유 또는 EDAM의 공식 제품이 아니며 이들과 제휴하거나 승인을 받은 제품이 아닙니다. 사용 권한이 있는 사진만 저장하고 게시자의 권리와 서비스 이용 조건을 지켜주세요.

소스와 사용 안내: https://github.com/hsofficial/nblogdl-chrome
문의와 오류 제보: https://github.com/hsofficial/nblogdl-chrome/issues
```

위 블록은 마크다운 장식 없는 스토어 입력용 문안입니다. 실제 다운로드 미검증 사실과 제출 전 조치 목록은 이 문서의 준비 안내에 따로 표시합니다. 스토어 상세 설명에 검증 완료·심사 승인·공식 제휴·3840픽셀 보장 등의 표현을 추가하지 않습니다.

## 권한 설명

현재 manifest에는 `storage`, `downloads`, `alarms`, `activeTab`과 아래 두 호스트가 선언되어 있습니다. **실제로 필요한 권한의 설명**과 **불필요한 선언을 제거해야 하는 항목**을 구분합니다. 현재 0.4.0을 수정하거나 새 패키지를 만들지는 않았습니다.

### storage: 복사용

```text
스캔한 게시글 제목·주소·이미지 주소·크기와 탭·문서 식별 정보를 chrome.storage.session에 임시 보관합니다. chrome.storage.local에는 다운로드 대기열·작업 상태·실제 파일 전체 경로·저장 폴더 설정·화면 모드와 최근 진행 로그를 보관하여 팝업 표시와 중단된 작업 복구에 사용합니다. 종료 작업은 최근 30개, 로그는 최근 60개이며 진행 작업은 유지합니다. storage.sync로 동기화하지 않습니다.
```

근거: [background.js](../extension/background.js)의 `transact`, `prune`, `view`, `route`; [theme.js](../extension/theme.js)의 `uiColorMode` 저장.

### downloads: 복사용

```text
사용자가 선택 저장 버튼을 눌러 만든 작업의 파일 다운로드 시작·상태 확인·취소·파일명 제안·실제 경로 확인과 저장 폴더 열기에 사용합니다. 복구 시 다운로드 ID 또는 후보 URL로 Chrome 다운로드 항목을 조회하고 이 확장의 항목과 대조합니다. 이 확장이 만든 파일로 확인되고 HTML·JSON 등 명시적인 비이미지 오류 응답일 때만 해당 오류 파일을 정리하고 다음 후보를 시도합니다. 파일 형식이 불확실한 경우에는 자동 삭제하지 않습니다.
```

근거: [background.js](../extension/background.js)의 `pump`, `settle`, `reconcile`, `CANCEL`, 다운로드 이벤트; [popup.js](../extension/popup.js)의 `chrome.downloads.show`. 다운로드 API 조회 결과를 개발자에게 보내지 않습니다.

### alarms: 복사용

```text
사용자가 이미 요청한 다운로드 작업의 상태와 대기열을 서비스 워커가 다시 확인하도록 queue-recovery 알람을 사용합니다. 진행 작업이 있을 때 0.5분 간격의 알람을 설정하고 작업이 없으면 해제합니다. 새 게시글을 자동 순회하거나 사용자 요청 없이 새 다운로드를 만드는 용도가 아닙니다.
```

근거: [background.js](../extension/background.js)의 `pump`, `chrome.alarms.onAlarm`, `reconcile`.

### activeTab: 제출 전 제거·검증 대상, 필요성 설명으로 복사하지 않음

현재 선언은 있으나 확인된 [popup.js](../extension/popup.js)는 `chrome.tabs.query({active: true, currentWindow: true})`에서 탭 ID를 얻고, 이미 주입된 콘텐츠 스크립트에 `tabs.sendMessage`로 재스캔을 요청합니다. [manifest.json](../extension/manifest.json)에 대상 두 호스트와 정적 콘텐츠 스크립트도 선언되어 있습니다. 이 호출 때문에 `activeTab`이 필수라고 설명할 수 없습니다.

Google의 [Excessive permissions 안내](https://developer.chrome.com/docs/webstore/troubleshooting#excessive-permissions)는 기본 현재 탭 조회·`tabs.sendMessage`·대상 호스트 접근이 있는 경우의 `activeTab` 불필요 사례를 명시합니다(Google, 확인 2026-10-15). 제출 후보에서 이 선언을 제거한 후 팝업·재스캔·선택 저장을 다시 확인하는 작업이 남았습니다. **그 조치를 하지 않은 현재 패키지는 제출 준비 완료가 아닙니다.**

### 호스트 https://blog.naver.com/*: 복사용

```text
PC 네이버 블로그 개별 게시글의 제목·게시글 식별 주소·본문 사진 메타데이터를 콘텐츠 스크립트로 읽어 미리보기와 선택 저장 목록을 만듭니다. PC 게시글이 mainFrame에 표시되는 구조를 지원하도록 일치하는 프레임에서도 실행합니다. 게시글 본문을 식별하지 못하면 다운로드 목록을 만들지 않습니다.
```

### 호스트 https://m.blog.naver.com/*: 복사용

```text
모바일 네이버 블로그 개별 게시글의 제목·게시글 식별 주소·본문 사진 메타데이터를 읽어 같은 미리보기와 선택 저장 목록을 제공합니다. 모바일 주소와 본문 구조를 지원하기 위한 접근이며 블로그 전체 글을 순회하지 않습니다.
```

두 호스트의 근거: [manifest.json](../extension/manifest.json)의 `host_permissions`, `content_scripts.matches`, `all_frames`; [content.js](../extension/content.js)의 `scan`; [core.js](../extension/core.js)의 `getPostIdentity`, `collectImages`; [background.js](../extension/background.js)의 `validateScan`. `all_frames`는 일치하는 호스트의 프레임 범위이며 임의 사이트에 대한 접근 권한은 아닙니다. 이미지 호스트는 [core.js](../extension/core.js)의 허용 목록과 manifest의 이미지 CSP에 별도로 제한되어 있습니다. 이미지 로딩 허용을 별도 `host_permissions` 선언으로 잘못 적지 않습니다.

| Website content / 웹사이트 콘텐츠 | 선택 권고. 제목·이미지 메타데이터·미리보기와 저장할 이미지 콘텐츠를 처리합니다. 본문 전체 텍스트를 서버에 업로드한다는 의미는 아닙니다. |
| Web history / 웹 기록 | 선택 권고. 대상 게시글 URL·블로그 식별자와 저장 요청한 게시글 기록을 기기에 보관합니다. `chrome.history`로 전체 브라우징 이력을 읽는 기능과는 다릅니다. |
| Personally identifiable information / 개인 식별 정보 | 별도 이름·이메일·연락처 입력 수집 기능은 없습니다. 다만 게시글 제목·블로그 식별자·사진·전체 파일 경로에 개인을 알아볼 정보가 포함될 수 있으므로 해당 정보가 전혀 없다고 보증하지 않습니다. 제출 화면의 정의가 이런 부수 정보를 포함하는지 확인하여 필요하면 추가 공개합니다. |
| Health / Financial and payment / Authentication / Personal communications | 해당 정보를 별도로 읽거나 입력받는 기능은 확인되지 않습니다. 사진이나 제목에 포함될 수 있는 콘텐츠를 분석해 이 범주별 프로필로 만드는 기능도 없습니다. 이를 근거로 원래 게시글 내용 자체에 민감 정보가 없다고 단정하지 않습니다. |
| Location / 위치 | GPS·위치 API로 위치를 얻는 기능은 없습니다. 네이버 이미지 요청에서 서버가 볼 수 있는 IP 등 일반 통신 정보는 아래 외부 요청 설명에 공개합니다. |
| User activity / 사용자 활동 | 광고·방문 분석을 위한 클릭·스크롤·키 입력 수집은 없습니다. DOM 변경·이미지 로드·주소 변경을 감지해 목록을 갱신하고, 저장 버튼·폴더 입력·화면 모드 선택을 기능 처리에 사용합니다. 제출 화면이 기능 조작까지 이 범주에 포함하면 추가 공개하고 처리방침과 일치시킵니다. |

입력 설명에 사용할 문장:

```text
네이버 블로그 게시글 제목·URL·이미지 URL과 크기 정보를 기기에서 처리하여 사진 미리보기와 수동 선택 저장을 제공합니다. 스캔은 세션 저장소에, 저장 요청 작업·실제 파일 전체 경로·설정·최근 로그는 로컬 확장 저장소에 보관합니다. 개발자 서버로 전송하거나 분석·광고 추적에 사용하지 않습니다. 사진을 표시하고 내려받기 위해 네이버 이미지 서버와 통신합니다. 웹사이트 콘텐츠와 대상 게시글 URL의 로컬 처리는 개인정보처리방침에 공개합니다.
```

데이터 사용 인증은 데이터 범주 선택과 별개입니다. 실제 제출자가 현재 후보와 [개인정보처리방침](../PRIVACY.md)을 확인한 후 다음 취지에 부합할 때만 인증합니다.

- 사용자 데이터를 판매하거나 광고·추적 목적으로 제3자에게 넘기지 않음.
- 공개한 단일 목적과 무관한 용도로 사용·전송하지 않음.
- 신용도 판단·대출 목적으로 사용·전송하지 않음.

확장에는 쿠키·비밀번호를 직접 읽는 API 호출이 없습니다. 다만 브라우저가 수행하는 네이버 이미지 요청에는 브라우저·서버 정책에 따른 IP·요청 헤더·허용된 쿠키 등 일반 요청 정보가 포함될 수 있으므로 “완전 오프라인”, “외부 전송 전혀 없음”, “쿠키 전송 절대 없음”이라고 쓰지 않습니다. 팝업 미리보기에는 `referrerPolicy = 'no-referrer'`가 설정되어 있으며 이 설정을 모든 다운로드 요청에 대한 보장으로 확대하지 않습니다.

Limited Use 공개 문구는 [PRIVACY.md의 제한된 사용](../PRIVACY.md#제한된-사용limited-use)에 포함했습니다. 기능과 문안의 일치 확인이며 Google 승인이나 법률 준수를 보증하는 인증서는 아닙니다.

## 심사자 테스트 안내: 복사용 초안

아래 절차는 심사자와 제출 전 검증자가 실행할 재현 안내입니다. **모든 단계가 실제 Chrome에서 통과했다는 결과 보고가 아닙니다.** 일반 게시글은 제목에 `아이유`가 없는, 로그인 없이 열리고 사진이 있는 공개 글로 제출 직전에 다시 확인합니다. 특정 공개 글은 삭제·권한 변경될 수 있습니다.

```text
이 확장은 네이버 블로그 개별 게시글에서 사진을 미리보고 수동으로 선택 저장합니다. 확장 자체의 별도 로그인이나 유료 계정은 필요하지 않습니다. 네이버 측에서 로그인·접근 제한을 표시하는 글은 사용할 수 없습니다.

1. 확장 설치 후 기존에 열려 있던 블로그 탭을 새로고침합니다. PC 예시 공개 게시글은 https://blog.naver.com/edament/224426042469 입니다. 이 주소는 과거 본문·사진 뷰어를 관찰한 예시이며 현재 접근 가능 여부와 사진 수는 다시 확인해주세요.
2. 본문을 읽어온 뒤 확장 팝업을 엽니다. 목록이 비어 있으면 본문을 스크롤하고 팝업의 다시 찾기를 누릅니다. 초기 사진은 선택되어 있지만 저장 버튼을 누르기 전에는 새 파일 저장이 시작되지 않습니다.
3. 전체 선택을 해제하고 사진 1~2장만 선택합니다. 하위 폴더에 NBlogReview 같은 상대 경로를 입력하고 선택한 이미지 저장 버튼을 누릅니다. 완료·실패·중지 상태, 완료 카드의 실제 경로, Chrome 다운로드 목록과 실제 파일을 확인합니다. 실제 픽셀 수와 이미지 형식은 파일을 열어 확인하며 w3840 요청만으로 크기를 추정하지 않습니다.
4. 작업이 진행 중이면 중지 버튼을 시험할 수 있습니다. 완료 파일이 있으면 저장 폴더 열기를 확인합니다. 팝업을 닫아도 이미 요청한 작업은 계속될 수 있습니다. 절대 경로와 ..가 포함된 하위 경로는 허용하지 않습니다.
5. 제목에 ‘아이유’가 포함된 예시 글에서는 응원봉 장식과 응원 문구를 표시합니다. 이는 읽어온 제목 문자열만으로 적용되는 로컬 UI 조건이며 계정·심사자·날짜를 판별하는 코드가 아닙니다. 시스템·라이트·다크 선택은 이 조건과 독립적입니다.
6. 시스템·라이트·다크를 각각 선택하고 팝업·오픈소스 안내에서 반영되는지 확인합니다. 시스템 모드에서는 OS/브라우저의 밝기 선호 변경을 따르고, 수동 모드에서는 선택을 유지합니다. 같은 제목에서 세 화면 모드 모두 제목 테마가 유지되는지 확인합니다. 테마가 활성인 팝업에서 연 안내 페이지는 ?theme=iu를 이어받습니다.
7. 제목에 ‘아이유’가 없는 일반 공개 사진 게시글로 이동한 뒤 팝업을 다시 엽니다. 기본 팔레트로 돌아가고 수동 화면 모드는 유지되어야 합니다. 일반 팝업에서 안내 페이지를 새로 열면 일반 팔레트입니다. 이미 열린 안내 페이지의 제목 테마가 이후 탭 이동까지 실시간으로 바뀌는 기능은 아닙니다.
8. 모바일 주소 https://m.blog.naver.com/edament/224426042469 에서도 접근 가능한 경우 목록·선택 저장을 확인합니다. 네이버의 리디렉션이나 접근 제한이 있으면 이를 기록합니다. 블로그 홈·검색 목록·다른 사이트에서는 개별 글 사진 목록을 생성하지 않습니다.

네트워크·게시글 구조에 따라 실패할 수 있으며 원본 또는 3840픽셀을 보장하지 않습니다. 본문에서 확인한 사진 수와 모든 글의 뷰어 수가 항상 같다고 보장하지 않습니다. NAVER, 아이유, EDAM과 제휴하지 않은 개인 오픈소스 도구입니다.
```

## 이미지와 실제 실행 검증의 경계

- 준비 이미지: 1280×800 PNG 5장. **샘플 데이터·모의 Chrome API로 만든 기능 소개 화면**이라는 표시를 유지합니다. [이미지 폴더](assets/)와 [생성 도구](generate-assets.cjs), [검증 도구](verify-assets.cjs)를 포함하며 생성 결과의 해상도·PNG 형식·문서 링크를 검사했습니다.
- 해당 이미지는 실제 게시글의 저작물을 저장한 증거나 Chrome 네이티브 다운로드 성공 기록이 아닙니다. 샘플 파일 경로·진행률·사진 개수를 실측 결과처럼 설명하지 않습니다.
- 연구노트 turn004의 GUI smoke는 실제 HTML/CSS 렌더링과 모의 확장 API를 사용했습니다. turn003의 실제 네이버 게시글 본문·뷰어 관찰은 있으나 그 사진 전체를 실제로 저장한 검증은 아닙니다.
- 제출 전 실제 Chrome에 **제출할 후보 패키지 자체**를 설치하여 일반 글·제목 테마 글에서 소량 저장, 폴더 열기, 파일 내용·형식·픽셀 크기, 중지, 세 화면 모드를 확인하고 결과를 기록해야 합니다. 현재 이 확인을 완료했다고 주장하지 않습니다.
- `activeTab` 정리, 공개 개인정보처리방침 접근 확인, 개인정보 범주·인증과 실제 후보 일치 확인 후에 제출 여부를 결정합니다. 현재 문서 준비는 제출·게시 승인이나 심사 통과를 뜻하지 않습니다.
